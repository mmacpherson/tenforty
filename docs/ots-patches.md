# Patches to vendored OpenTaxSolver

We vendor OpenTaxSolver (OTS); we do not fork it. `ots/amalgamate.py` turns
the tracked release tarballs into `src/tenforty/otslib/ots_amalgamation.cpp`.
The only edits it may make to OTS source are:

- **portability**, which covers exactly two things and nothing else:
  - making the source compile as C++;
  - the narrow executable-to-library control-flow adaptation, where an entry
    point returns an error instead of terminating the host process.

  State resets are not portability.
- **memory safety**: stopping reads or writes out of bounds or of
  uninitialised memory.

One entry is outside both classes and is tolerated only until it is removed:
OTS-P4, the `do_all_caps` reset. That reset moves into the Cython binding
under tenforty-0qmf.

Even these must not change a figure OTS computes on a platform where the
original source is well defined. A tax-logic defect is never patched: it is
reported upstream and recorded as a strict-xfail (see `AGENTS.md`).

Every patch is registered in `ots/ots_patches.py`. This page shows that
registry, and `tests/ots_patch_registry_test.py` fails if the two disagree.

## What a patch needs

1. **A registry entry** in `ots/ots_patches.py`:
   - an ID (`OTS-Pn`, numbered in order) and the patch function's name;
   - a class, `portability` or `memory-safety` and nothing else;
   - its scope, plus the exact number of matches it makes in each program and
     year;
   - its effect on computed figures, with the reasoning;
   - a status, the upstream report, and its witnesses.
2. **A source witness** in `tests/ots_patch_registry_test.py`: a predicate
   that finds the defect in the *unpatched* source of the tracked tarballs.
   - The witness must find the defect in exactly the programs and years the
     entry patches.
   - Where feasible, add a **behavioral witness**: a test that runs the
     unpatched program and shows the defect changing a result. An
     uninitialised read, for example, can be made deterministic by compiling
     with clang's `-ftrivial-auto-var-init=pattern` against `=zero`.
     - A behavioral witness skips, rather than fails, when its toolchain is
       missing, and it is not graph-marked.
     - If the unpatched program fails earlier on another registered defect,
       the witness applies that patch first, and the entry names it in
       `witness_depends_on`.
3. **An upstream report** staged in `docs/upstream-ots-reports.md`, drafted
   only; Mike sends.
   - A portability change needs none when the original is correct for how OTS
     is meant to be built and run, as standalone C programs. The entry says
     so.
4. **An exact match.** The patch function returns how many matches it made.
   - `amalgamate.py` runs every active patch on every program and stops with
     `PatchMatchError` if any count differs from the registry, including a
     match outside the registered scope.
   - So when a new OTS release changes the code a patch targets, regeneration
     fails loudly instead of silently patching less, or more.

## Lifecycle

| Status | Meaning |
|---|---|
| `active` | Applied; no upstream report is needed or staged. |
| `reported-upstream` | Applied; an upstream report is drafted or sent. |
| `fixed-upstream` | Applied to the tracked releases that still have the defect; a later OTS release has fixed it. |
| `pending-replacement` | Applied, but not an allowed class; the entry names the bead that replaces it outside the vendored source. Only OTS-P4. |
| `retired` | The function is removed. The entry stays as the history record, with the date and the release that made it unnecessary. |

**Retiring a patch.**
1. When a tracked release no longer has a defect, its source witness fails
   and says *retire OTS-Pn (or narrow its scope), update the registry*, the
   way a strict xfail flips once a release carries the correction.
2. Remove the patch function, or narrow its `matches`.
3. Set the status to `retired` with the date and the release, and regenerate.

**Restoring a patch.** A retired entry's witness asserts the defect stays
absent. If a new tarball reintroduces the defect, the witness fails and says
to restore the patch.

**Regenerating.** Run `uv run make -C ots generated install` (it runs
`amalgamate.py` over every tarball in `ots/ots-releases/`), then the
pre-commit hooks.
`test_committed_amalgamation_is_what_the_registry_generates` checks that the
committed amalgamation is exactly what the registry produces.

**Re-rendering this page.** Run `uv run python ots/ots_patches.py` after
changing the registry; the section below is generated.

### OTS-P1: Rename the C++ reserved word `new` in `add_pdf_markup`.

- **Patch function:** `patch_add_pdf_markup`
- **Class:** portability
- **Scope:** taxsolve_routines.c, 2018-2025
- **Required matches:** 2018-2020: routines 9; 2021-2025: routines 14 (whole-word `new` tokens renamed `_new` in the function body)
- **Effect on computed figures:** None on any platform: a local identifier is renamed consistently within one function, so the compiled code is the same.
- **Status:** active
- **Upstream:** Not applicable: OTS ships C, where `new` is an ordinary identifier. Compiling it as C++ is our choice, not an upstream defect.
- **Source witnesses:** `tests/ots_patch_registry_test.py::test_source_witness[OTS-P1]`

### OTS-P2: Cast `memset(malloc(...))` to `char*` in `mystrndup`.

- **Patch function:** `patch_mystrndup_cpp_compat`
- **Class:** portability
- **Scope:** taxsolve_routines.c, 2025
- **Required matches:** 2025: routines 1 (casts added)
- **Effect on computed figures:** None on any platform: C converts the `void*` to `char*` implicitly; the cast states the same conversion for C++.
- **Status:** active
- **Upstream:** Not applicable: the implicit `void*` conversion is valid C. Compiling it as C++ is our choice.
- **Source witnesses:** `tests/ots_patch_registry_test.py::test_source_witness[OTS-P2]`

### OTS-P3: Turn `exit(N)` in each program's `main` into a flushed `return N`.

- **Patch function:** `patch_exit_to_return`
- **Class:** portability
- **Scope:** every form program, 2018-2025
- **Required matches:** 2018-2025: every form program 1 (`main` bodies rewritten (with no `exit(` left in them))
- **Effect on computed figures:** Same error status; no intended change to any successful computation. The rewrite touches only the paths where `main` ends the program: OTS's `exit` would end the Python process, and the `return` hands the Cython wrapper the same status after flushing the output file, as `exit` would have.
- **Status:** active
- **Upstream:** Not applicable: OTS is a set of command-line programs, for which `exit` is correct. Running them in-process is our choice.
- **Source witnesses:** `tests/ots_patch_registry_test.py::test_source_witness[OTS-P3]`, `tests/ots_patch_registry_test.py::test_exit_rewrite_follows_main_braces_only`
- **Note:** Approved as portability by Mike's ruling of 2026-11-06: an entry point that returns an error instead of terminating the host process is the one control-flow adaptation portability covers. Not contained: the 302 `exit()` calls in helper functions outside `main` (all years, routines included) still end the interpreter. For example, `evaluate_form(year=2024, federal_form_id='US_1040', federal_form_values={'L1a': 'not-a-number'})` exits the Python process with status 1 and no traceback.

### OTS-P4: Reset `do_all_caps` to 0 at the top of each program's `main`.

- **Patch function:** `patch_reset_globals`
- **Class:** none: state restoration, slated for removal
- **Scope:** every form program, 2018-2025
- **Required matches:** 2018-2025: every form program 1 (resets inserted)
- **Effect on computed figures:** None on computed figures: `do_all_caps` only upper-cases imported names and paths. A fresh OTS process starts with it 0; the reset gives every in-process run that same start, so a later program does not read file paths upper-cased by an earlier NC, OH or PA run.
- **Status:** active, pending replacement (tenforty-0qmf)
- **Upstream:** Not applicable: each OTS program runs in a fresh process, where the flag starts at 0. Reusing one process is our choice.
- **Source witnesses:** `tests/ots_patch_registry_test.py::test_source_witness[OTS-P4]`
- **Note:** Not an allowed class. Mike ruled on 2026-11-06 that a state reset is not portability, so the reset moves into the Cython binding in a follow-up PR. That PR removes this patch, and its 140 insertions change ots_amalgamation.cpp. Until then this is the one entry the class test tolerates outside portability and memory-safety.

### OTS-P10: Zero-initialise OR-40's `SchA_L`, whose line 8 is summed but never set.

- **Patch function:** `patch_or_40_sch_a_zero_init`
- **Class:** memory-safety
- **Scope:** OR_40, 2024-2025
- **Required matches:** 2024-2025: OR_40 1 (declarations given `= {0}`)
- **Effect on computed figures:** None where the read was already 0, as on our Linux builds. Schedule OR-A line 9 adds `SchA_L[8]`, which nothing assigns, so line 9 and the Oregon itemized deduction took whatever was on the stack: a 2024 Single $420,000 return deducted $10,000 instead of the $2,745 standard deduction on an Intel macOS build. - **Status:** reported-upstream

- **Source witnesses:** `tests/ots_patch_registry_test.py::test_source_witness[OTS-P10]`

- **Witness applies first:** OTS-P6
- **Note:** Built with clang's `-ftrivial-auto-var-init=pattern`, the unpatched program makes the read a NaN and deducts the full line 9 limit; with the patch, pattern and `=zero` builds print the same return. The witness applies OTS-P6 first, because at -O0 the 2024 program otherwise crashes on the empty dependent names before Schedule OR-A.

## Changes that are not patches

`amalgamate.py` also restructures the source without changing any statement
OTS executes, so these are not registered. It:

- wraps each release in a year namespace, and each program in a nested
  namespace;
- inlines `taxsolve_routines.c` once per year, and
  `taxsolve_get_fed_return_data.c` into each AZ program;
- `#undef`s each program's `#define`s at the end of its namespace, so that
  macros do not leak between programs.

## Removed without a registry entry

`patch_sched1a_line29_label` relabelled one printed output line of the 2025
federal program, from `"S1A_20", sched1A_L[20]` to `"S1A_29", sched1A_L[29]`.

- It was neither portability nor memory safety, so it could not be
  registered, and it was removed on 2026-11-06.
- Removing it changes one raw OTS diagnostic output key. The 2025 federal
  program's raw printed output, and so the raw key dictionary `evaluate_form`
  returns, no longer has an `S1A_29` key. Where it was, upstream prints
  `sched1A_L[20]` a second time under `S1A_20`. So the change is not neutral
  for raw OTS output.
- No computed tax amount or mapped tax result changes. `sched1A_L[29]` and
  its use on line 30 are untouched, and no mapped tax input or output in
  `src/` reads the `S1A_20` or `S1A_29` key.
- The upstream slip is still in report 12 of `docs/upstream-ots-reports.md`.
